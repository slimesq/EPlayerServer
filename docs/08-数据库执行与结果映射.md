# EPlayerServer 阶段八 数据库执行与结果映射

本章进入两种后端的真实执行路径，说明连接参数、查询、列字节复制、结果对象与事务如何组合。上一章的表模板负责布局，本章客户端负责执行并填充。

源码入口：[Sqlite3Client.cpp](../src/Sqlite3Client.cpp)、[MysqlClient.cpp](../src/MysqlClient.cpp)、[DatabaseHelper.h](../inc/DatabaseHelper.h)、[登录中的数据库锁](../src/EdoyunPlayerServer.cpp)。

## 1. 同一接口下的两类数据库

| 对比 | SQLite | MySQL |
| --- | --- | --- |
| 执行位置 | 当前应用进程里的库 | 外部数据库服务 |
| Connect 的 host | 文件路径或 :memory: | 主机地址 |
| 其他参数 | 当前主要使用 host | user、password、db、port |
| 底层对象 | sqlite3* 和本地语句 | MYSQL 连接与 MYSQL_RES |
| 登录主线 | 未选择 | 当前使用 |

Connect 的 KeyValue 统一了键值输入形式，不代表两个后端所有参数含义相同。SQL 方言、字段布局和错误约定也没有被共同基类完全抹平。

## 2. SQLite Connect 与句柄

```cpp
int CSqlite3Client::Connect(KeyValue const& args)
{
    auto it = args.find("host");
    if (it == args.end())
        return -1;
    if (m_db != NULL)
        return -2;
    int ret = sqlite3_open(it->second, &m_db);
    if (ret != 0)
    {
        TRACEE("connect failed:%d [%s]", ret, sqlite3_errmsg(m_db));
        return -3;
    }
    return 0;
}
```

sqlite3_open 按路径打开文件，也可用 :memory: 建立当前连接的内存数据库。不是发起一个到名为路径的主机的网络请求。

调用方以 Connect 返回值判断成功。IsConnected 仅检查内部指针，未表达一整套健康状态；取得句柄和完整成功状态不应凭一个字段随意替换。

## 3. SQLite 无结果执行

```cpp
int CSqlite3Client::Exec(Buffer const& sql)
{
    printf("sql={%s}\n", (char*)sql);
    if (m_db == NULL)
        return -1;
    int ret = sqlite3_exec(m_db, sql, NULL, this, NULL);
    if (ret != SQLITE_OK)
    {
        printf("sql={%s}\n", (char*)sql);
        printf("Exec failed:%d [%s]\n", ret, sqlite3_errmsg(m_db));
        return -2;
    }
    return 0;
}
```

sqlite3_exec 执行文本，本重载不保存查询行。参数中的回调为 nullptr，因此即使 SQL 能产生行，也不会转换成 Result。

前面的 SQL printf 是现有实现的输出，不是框架自动产生可回滚执行计划。生成 SQL 与实际执行依然是两步。

## 4. SQLite 有结果执行

```cpp
int CSqlite3Client::Exec(Buffer const& sql, Result& result, _Table_ const& table)
{
    if (!m_db)
        return -1;
    sqlite3_stmt* statement = nullptr;
    if (sqlite3_prepare_v2(m_db, sql.data(), int(sql.size()), &statement, nullptr) != SQLITE_OK)
        return -2;
    int status;
    while ((status = sqlite3_step(statement)) == SQLITE_ROW)
    {
        PTable record = table.Copy();
        for (int i = 0; i < sqlite3_column_count(statement); ++i)
        {
            auto field = record->Fields.find(sqlite3_column_name(statement, i));
            if (field == record->Fields.end() || sqlite3_column_type(statement, i) == SQLITE_NULL)
                continue;
            auto* value = static_cast<char const*>(sqlite3_column_blob(statement, i));
            field->second->LoadFromStr(
                Buffer(value ? value : "", sqlite3_column_bytes(statement, i)));
        }
        result.push_back(std::move(record));
    }
    sqlite3_finalize(statement);
    return status == SQLITE_DONE ? 0 : -2;
}
```

实际链为：

```text
prepare_v2
  → step 返回 SQLITE_ROW
  → table.Copy
  → 对每列按名字找到字段
  → 复制该列的实际 bytes
  → LoadFromStr 转成字段值
  → push 到 Result
  → 继续 step
  → finalize
```

头文件里还保留 m_stmt 和 ExecCallback，但当前有结果重载使用自己的局部 statement 与 step 路径。不能看到旧回调名字就把它当成真实执行入口。

## 5. prepare、step、列访问和 finalize

| 调用 | 关键参数或返回值 | 生命周期含义 |
| --- | --- | --- |
| prepare_v2 | 连接、SQL 地址、字节数、输出 statement | 创建可执行语句对象 |
| step | statement，返回 ROW/DONE/错误 | 推进语句执行 |
| column_name | statement、列下标 | 按数据库返回名称映射字段 |
| column_blob / column_bytes | 同一列 | 取得字节地址及实际长度 |
| finalize | statement | 释放语句资源 |

column_blob 名字不表示 schema 的所有列都是 BLOB。SQLite 会按访问接口提供相应转换，数值列之后再由 LoadFromStr 读成 Integer 或 Double。

返回的列地址由 SQLite 管理，不能不加复制地保存到后续 step 或 finalize 之后。当前立即构造 Buffer，字段再复制，结果对象才独立于语句寿命。取列规则见 [SQLite 列接口](https://www.sqlite.org/c3ref/column_blob.html)。

prepare 并不自动完成参数化：当前没有占位符与 sqlite3_bind。已有用户值仍通过 SQL 文字转换进入语句。

## 6. 两行结果的具体推演

假设表模板有 id 和 name，数据库返回：

| 数据库行 | id | name |
| --- | ---: | --- |
| 第一行 | 1 | alpha |
| 第二行 | 2 | beta |

```text
step 第一行 → Copy 出 row A → A 字段写入 1、alpha → result.push(A)
step 第二行 → Copy 出 row B → B 字段写入 2、beta  → result.push(B)
step DONE   → finalize
```

A 与 B 的字段地址不同，字符串 Buffer 也不同。修改 A 的 name 不会变 B；原模板仍保存它自己的值。结果不是一个对象被反复改写后保存了多份相同指针。

## 7. MySQL Connect 的准备步骤

```cpp
int CMysqlClient::Connect(KeyValue const& args)
{
    if (m_bInit)
        return -1;
    for (auto key : {"host", "user", "password", "db", "port"})
        if (args.find(key) == args.end())
            return -1;
    MYSQL* ret = mysql_init(&m_db);
    if (ret == NULL)
        return -2;
    unsigned timeout = 3;
    mysql_options(&m_db, MYSQL_OPT_CONNECT_TIMEOUT, &timeout);
    mysql_options(&m_db, MYSQL_SET_CHARSET_NAME, "utf8mb4");
    ret = mysql_real_connect(&m_db,
                             args.at("host"),
                             args.at("user"),
                             args.at("password"),
                             args.at("db"),
                             atoi(args.at("port")),
                             NULL,
                             0);
    if ((ret == NULL) && (mysql_errno(&m_db) != 0))
    {
        fprintf(stderr, "%s %d %s\n", __FUNCTION__, mysql_errno(&m_db), mysql_error(&m_db));
        TRACEE("%d %s", mysql_errno(&m_db), mysql_error(&m_db));
        mysql_close(&m_db);
        bzero(&m_db, sizeof(m_db));
        return -3;
    }
    m_bInit = true;
    return 0;
}
```

### 7.1 参数和初始化

要求五个键都存在。mysql_init 准备客户端对象，mysql_options 设置约三秒连接超时与 utf8mb4，mysql_real_connect 连接指定数据库。

db 必须事先存在，程序建表不建库。参数来自环境变量，但 Connect 只看到已经组成的 KeyValue，不直接读 .env。

### 7.2 本地状态不等于持续在线

成功后 m_bInit=true，Close 再置 false。IsConnected 返回这个标志，不进行网络探测，也没有自动重连和恢复事务的协议。

底层连接失败会输出库错误并返回包装错误码；BusinessProcess 再映射自己的初始化状态，不能把各层同号负数当成同一个原因。

## 8. MySQL 查询与结果映射

```cpp
int CMysqlClient::Exec(Buffer const& sql, Result& result, _Table_ const& table)
{
    if (!m_bInit)
        return -1;
    int ret = mysql_real_query(&m_db, sql, sql.size());
    if (ret != 0)
    {
        fprintf(stderr, "%s %d %s\n", __FUNCTION__, mysql_errno(&m_db), mysql_error(&m_db));
        TRACEE("%d %s", mysql_errno(&m_db), mysql_error(&m_db));
        return -2;
    }
    MYSQL_RES* res = mysql_store_result(&m_db);
    if (!res)
        return -2;
    MYSQL_FIELD* fields = mysql_fetch_fields(res);
    MYSQL_ROW row;
    unsigned count = mysql_num_fields(res);
    while ((row = mysql_fetch_row(res)))
    {
        PTable record = table.Copy();
        unsigned long* lengths = mysql_fetch_lengths(res);
        for (unsigned i = 0; i < count; ++i)
        {
            auto field = record->Fields.find(fields[i].name);
            if (field != record->Fields.end() && row[i])
                field->second->LoadFromStr(Buffer(row[i], lengths[i]));
        }
        result.push_back(std::move(record));
    }
    mysql_free_result(res);
    return 0;
}
```

| 对象或调用 | 保存什么 |
| --- | --- |
| mysql_real_query | 发送带显式长度的 SQL |
| MYSQL_RES | 客户端取得的结果集 |
| mysql_fetch_fields | 返回列的名称等元数据 |
| MYSQL_ROW | 当前行每列地址，SQL NULL 为 nullptr |
| mysql_fetch_lengths | 每列实际长度 |
| PTable record | 当前行的独立 C++ 对象 |

使用真实长度，才能保留含零的二进制值。最终 mysql_free_result 后，C++ 记录仍有效，是因为列内容已被复制，而不是结果集永久保持打开。

SELECT 没找到行仍是成功查询，rows 为空；不能把它等同为 SQL 执行失败。结果语义见 [mysql_store_result 文档](https://dev.mysql.com/doc/c-api/8.0/en/mysql-store-result.html)。

无结果 Exec 仅调用 real_query，不消费 SELECT 的结果集；查询应使用有结果重载，不能把两个重载当成随意互换的输出形式。

## 9. Result 是追加输出

两个后端都 push_back，不会在开始时自动 clear：

```text
第一次 SELECT 返回 2 行 → Result.size() = 2
复用同一 Result 再查 2 行 → Result.size() = 4
```

登录每次声明新的局部 Result，所以不混入前一个请求。其他调用方复用容器时必须明确何时清空，并先检查返回码再消费数据；容器已有一些行并不能独立证明本次执行完整成功。

## 10. LoadFromStr 的类型解释

| nType | 当前转换 | 保存位置 |
| --- | --- | --- |
| BOOL、INT、DATETIME | atoi | Value.Integer |
| REAL | atof | Value.Double |
| VARCHAR、TEXT、BLOB | Buffer 复制 | *Value.String |
| NULL | 不加载 | 保持当前状态 |

业务表的某些 SQL DATETIME 字段还声明为 TYPE_INT，日期文字会被 atoi 当整数前缀读，不能保存完整日期时间。SQL 类型文字与 C++ 类型标签的对应必须一致设计。

## 11. SQL NULL 的模板残留

当前两个映射器看到 NULL 都跳过字段赋值。如果模板 name 已为 template-value，而查询该列为 NULL：

```text
Copy 模板 → name 已是 template-value
发现数据库列为 NULL → 跳过 LoadFromStr
最终行 name 仍是 template-value
```

这不是数据库把 NULL 转成了该文字，而是模板值被保留。模型缺少独立 null 标记，不能可靠地区分 NULL、零、空字符串与未加载。

## 12. Escape 与实际查询锁

```cpp
Buffer CMysqlClient::Escape(Buffer const& value)
{
    if (!m_bInit)
        return {};
    Buffer escaped(value.size() * 2 + 1);
    escaped.resize(
        mysql_real_escape_string_quote(&m_db, escaped.data(), value.data(), value.size(), '\''));
    return escaped;
}
```

逃逸缓冲按最坏长度准备，mysql_real_escape_string_quote 基于当前连接与引号规则转换，再按真实输出缩小。

登录在同一把 m_databaseMutex 内执行 Escape、table.Query 和 Exec，因为共享的是一条连接。Query 接受任意条件文字，并不会对整段 condition 再做自动安全转换。

```text
输入 user → 作为值转义 → 拼成 user_name='...'
         → 表生成 SELECT → 同一连接执行
```

字段 toSqlStr 的十六进制文字是另一条序列化路径，与这个用户名条件的连接专用 Escape 不同。

## 13. 事务与共享连接的边界

事务把一组数据库操作放在一次提交或回滚的边界内。例如一次转账有扣款和入账两步，需要把两步作为一个工作单元处理。BEGIN 开始事务，COMMIT 提交，ROLLBACK 撤销未提交修改；具体保证还受数据库与存储引擎规则约束。

Start、Commit、Rollback 最终分别发送 BEGIN、COMMIT、ROLLBACK。事务属于数据库连接，不属于某条 C++ 工作线程。

```text
线程 A：BEGIN
线程 B：在同一连接执行一条写入
线程 A：ROLLBACK
```

若只为每次单独 Exec 加锁，B 仍可能插入 A 的事务区间。多条语句构成事务时，连接锁需要覆盖整个事务，或由独占连接安排执行。

当前登录只是一次查询，不使用这段事务流程。接口也没有 RAII 事务对象替异常路径自动回滚；调用方仍需决定提交与回滚。

## 14. 释放顺序与所有权

```text
SQLite：step/读取 → 复制列 → finalize → 行继续存活
MySQL：fetch/读取 → 复制列 → free_result → 行继续存活
连接：业务不再执行查询 → Close
```

结果用 shared_ptr 管行寿命，客户端负责底层句柄，字段负责自己的字符串内存。这些责任不能因为统一叫“数据库模块”就合并为一个析构点。

## 15. 数据访问设计的定位

具体客户端是 C API 的适配者；行填充具有 Data Mapper 的部分意图；Copy 是 Prototype 的落点。当前仍把 schema 和行值放一起，业务直接知道 SQL 和字段名，尚未隔离成纯领域数据访问接口。
